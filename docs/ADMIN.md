# 管理介面操作手冊（Sveltia CMS）

網址：**https://tiong-ui.github.io/look-back/admin/**

用網頁表單新增、修改事件、地點、參考資源與時代，不需要寫程式。按「儲存」後，資料會直接存到 GitHub，網站約 2–3 分鐘後自動更新。

---

## 一、第一次登入：建立 GitHub 存取權杖

管理介面使用「存取權杖」登入。這個權杖等於一把只能開這個專案的鑰匙，每位編輯者用自己的 GitHub 帳號各建一個。

1. 登入 GitHub，打開 **Settings → Developer settings → Personal access tokens → Fine-grained tokens**（網址：https://github.com/settings/personal-access-tokens/new ）。
2. 填寫：
   - **Token name**：`look-back CMS`
   - **Expiration**：選擇期限，例如 1 年。到期後重新建立一個即可。
   - **Repository access**：選 **Only select repositories** → 勾選 `tiong-ui/look-back`
   - **Permissions → Repository permissions → Contents**：選 **Read and write**
3. 按 **Generate token**，複製產生的權杖（`github_pat_` 開頭）。**這串權杖只會顯示一次**，請先存好。
4. 打開管理介面，按 **「使用存取權杖登入」**，貼上權杖。

> **注意**：權杖請當作密碼保管，不要分享給別人。萬一外流，到同一個頁面按 Revoke（撤銷）即可作廢。
> 其他人要協助編輯時，請先在 GitHub 專案 **Settings → Collaborators** 加入他的帳號，再由他用自己的帳號建立權杖。

## 二、從書本新增一筆事件

**步驟 1：先登錄這本書**（同一本書只需登錄一次）
1. 左側選 **參考資源** → 按 **新增**。
2. 填寫：
   - **編號**：英文，例如 `zhou-wanyao-illustrated`
   - **名稱**：中文填「作者《書名》」，例如 `周婉窈《臺灣歷史圖說》`
   - **類型**：選 **書籍**
   - **語言**：勾選書的語言
3. 按 **儲存**。這本書也會出現在網站的「參考資源」頁。

**步驟 2：確認地點已存在**
1. 左側選 **地點**，搜尋地名。
2. 找不到就按 **新增**，填寫編號、經緯度和名稱。
   - **經緯度**：在 Google 地圖對地點按右鍵，會顯示「緯度, 經度」，例如 `23.0016, 120.1606`；第一個數字是**緯度**，第二個是**經度**。
   - **不同時代的名稱**：可以分別填寫，例如 大員（到 1661 年）、安平（1662 年起）。

**步驟 3：新增事件**
1. 左側選 **歷史事件** → 按 **新增**。
2. 必填欄位：
   - **編號**：英文，例如 `tapani-incident`。建立後請不要再改。
   - **標題**、**摘要**：摘要請依 [編輯準則](EDITORIAL.md)，以臺灣主體觀點書寫兩三句。
   - **開始日期**：年份用「天文紀年」，西元後照寫。西元前要換算：西元前 1 年填 `0`，西元前 200 年填 `-199`。
   - **日期精確度**：只知道年份就選「年」。
   - **分類**、**地區**
   - **地點**：選剛才的地點，並設定角色。「出發地」加「目的地」會在地圖上畫出移動路線。
3. 選填：
   - **相關事件**：例如「屬於 日治時期」。
   - **各方觀點**：有爭議的事件，列出不同觀點。
   - **資料來源**：選剛才登錄的書，並填頁碼，例如 `p.215`。
4. 按右上角 **儲存**。2–3 分鐘後重新整理網站就會看到。

## 三、修改或刪除事件

- **修改**：在 **歷史事件** 搜尋，點進去改完按儲存即可。
- **修改來自維基數據的事件**：編號 `wd-` 開頭的就是。你修改過的內容，之後自動匯入時**不會被覆蓋**。
- **刪除**：點進事件 → 右上角選單 → 刪除。
  - **來自維基數據的事件**：刪除後，請到 **排除清單** 加入它的維基數據編號（例如 `Q12345`，在事件的「維基數據編號」欄位），否則下個月匯入時會再出現。

## 四、小技巧

- **篩選**：列表上方可以篩選「臺灣」「來自維基數據」「手動建立」，也可以依年份或重要度排序。
- **重要度**：有維基百科條目的事件，每月會依維基百科重新計算重要度。想固定自己設定的分數，請勾選 **鎖定重要度**。
- **改錯了**：每次儲存都會在 GitHub 留下紀錄，可以到專案的 **Commits** 頁面找回舊版本，或請 Claude 協助還原。
- **網站沒更新**：到 GitHub 專案的 **Actions** 頁面，看「Deploy to GitHub Pages」是否完成。如果出現紅色 ✗，通常是某個欄位格式有誤，點進去可以看到是哪個檔案的問題。

## 維護者備註

- 設定檔：`public/admin/config.yml`。欄位規則要和 `scripts/build-data.ts` 的檢查保持一致。
- Sveltia CMS 固定使用的版本寫在 `public/admin/index.html`。升級時修改版本號即可，並先在本機確認可以開啟。
- 如果將來想改用「用 GitHub 帳號登入」（OAuth），需要另外部署 [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth)（Cloudflare Workers，免費），並在 `backend` 加上 `base_url`。
