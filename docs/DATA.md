# Data guide（資料編輯指南）

All content lives in `data/`, **one YAML file per record**, named after the record's id. There are three ways to change it, and they all edit the same files:

1. **The CMS** at https://tiong-ui.github.io/look-back/admin/: forms, no YAML needed. See [ADMIN.md](ADMIN.md) (中文操作手冊).
2. **By hand**: edit the YAML files and commit.
3. **The Wikidata importer**: adds and refreshes events automatically (see below).

`npm run data` (run automatically by `npm run dev` and `npm run build`) checks everything and writes `public/data/atlas.json` for the app. If something is wrong, it prints the file and the problem.

| Path | What it holds | In the CMS |
|---|---|---|
| `data/events/<id>.yaml` | Historical events: curated, from books, and imported from Wikidata | 歷史事件 |
| `data/places/<id>.yaml` | Places: coordinates and period-appropriate names | 地點 |
| `data/resources/<id>.yaml` | Reference list (參考資源): sites, archives, **books**. Events cite these | 參考資源 |
| `data/eras/<id>.yaml` | Timeline presets | 時代 |
| `data/excluded.yaml` | Wikidata IDs the importer must never import | 排除清單 |
| `data/config.yaml` | Viewpoints, region importance boost, era groups, resource types | (edit by hand) |
| `data/importance.json` | Generated by `npm run importance`; don't edit | — |

The file name must match the record's `id` (the build checks this). Empty optional fields are ignored, so the blanks the CMS leaves are fine.

## Years

Years are **astronomical**: 1 BC = `0`, 2 BC = `-1`, 200 BC = `-199`, AD 1 = `1`. (The historical calendar has no year 0.) The timeline runs from `-29999` (30,000 BC) to `2026`.

## An event

`data/events/siege-of-fort-zeelandia.yaml`:

```yaml
id: siege-of-fort-zeelandia            # unique, lowercase-kebab-case = file name
title: { zh-TW: 熱蘭遮城之役, en: Siege of Fort Zeelandia }
altNames:                              # optional
  - { zh-TW: …, en: … }
summary:
  zh-TW: …
  en: …
start: { year: 1661, month: 4, day: 30 } # or just: start: 1661
end: { year: 1662, month: 2, day: 1 }    # optional
precision: day                         # day | month | year | decade | century | millennium
approximate: false                     # true shows "約 / c."
categories: [war]                      # see src/lib/categories.ts
regions: [taiwan]                      # `taiwan` gets an importance boost
importance: 4                          # 1–5; replaced monthly by the Wikipedia score unless importanceLocked
importanceLocked: false
importanceBoost: 0                     # optional, -2..2, nudges the Wikipedia score
locations:
  - { place: tainan-anping, role: primary }
  - { place: xiamen, role: origin }        # origin → destination draws an arc
  - { place: tainan-anping, role: destination }
relations:                             # the inverse is added automatically
  - { event: dutch-formosa, type: part_of }
perspectives:                          # for contested events, see EDITORIAL.md
  - view: taiwan
    text: { zh-TW: …, en: … }
wikipedia: { en: Siege of Fort Zeelandia, zh: 熱蘭遮城之役 }  # article titles → links + importance
wikidata: Q1234567                     # optional
sources:
  - { resource: andrade-lost-colony, page: "p.215" }   # a book from data/resources/
  - { url: "https://…", title: { zh-TW: …, en: … } }   # a specific web page
```

**Location roles:** `primary`, `secondary`, `origin`, `destination` (every origin is linked to every destination with an animated arc), `area`.
**Relation types:** `causes`, `caused_by`, `part_of`, `has_part`, `precedes`, `follows`, `related`.

```yaml
type: book            # see resourceTypes in config.yaml
lang: [zh, en]
url: https://…        # optional for books
```

## Wikidata import（自動匯入）

`npm run import` (`scripts/import-wikidata.ts`), run monthly and on demand by the *Import events from Wikidata* workflow, pulls events in Asia from Wikidata. It covers battles, wars, sieges, invasions, treaties, rebellions, revolutions, coups, massacres, protests, earthquakes, epidemics, major elections and other historical events. An event qualifies if it has a date, coordinates in Asia, and enough Wikipedia language editions; events in Taiwan, Penghu, Kinmen and Matsu need only 2, and are found through QLever.

Imported events are ordinary records in `data/events/`, with ids `wd-q<number>`. The import **merges**:

- **New events** and places are added.
- **Untouched events** that the importer wrote earlier are refreshed from Wikidata. Each one stores an `importHash` fingerprint of its content, so the importer can tell it hasn't been changed.
- **Edited events** are never overwritten, and neither are curated events. As soon as an event is edited, in the CMS or by hand, its content no longer matches its `importHash`.
- **Files are never deleted.** To get rid of an imported event for good, delete it *and* add its Wikidata ID to the 排除清單 (`data/excluded.yaml`).

The workflow opens a pull request with the changes.

## Importance（重要度）

"Major" events are decided from Wikipedia. `npm run importance` (monthly, *Refresh importance* workflow) reads each event's `wikipedia` titles and fetches:

- the number of Wikipedia language editions (Wikidata);
- page views on English and Chinese Wikipedia over the last 12 months.

These are log-scaled into a 1–5 score (`src/lib/importance.ts`), with +1 for regions in `regionBoost` (`taiwan`), plus `importanceBoost`. Events with `importanceLocked: true` keep their own `importance`.

The wider the selected time range, the higher the minimum importance shown: > 1,000 years → 4+, > 200 → 3+, > 50 → 2+, otherwise all. "Show all" turns this off.
