# Data guide（資料編輯指南）

All content lives in `data/` as YAML that people can edit directly. `npm run data` (run automatically by `npm run dev` and `npm run build`) checks everything and writes `public/data/atlas.json` for the app. If something is wrong, it prints the file, the entry and the problem.

| File | What it holds |
|---|---|
| `data/events/*.yaml` | Historical events. Any number of files; they are merged. |
| `data/places.yaml` | Gazetteer: coordinates and period-appropriate names. |
| `data/eras.yaml` | Timeline presets (eras). |
| `data/resources.yaml` | **The resource-links list** (參考資源). Shown in the app; events can cite entries. |
| `data/config.yaml` | Viewpoints, region importance boost, era groups, resource types. |
| `data/importance.json` | Generated by `npm run importance` (Wikipedia signals). Don't edit by hand. |
| `data/imported/*.yaml` | Generated by `npm run import` (events and places from Wikidata). Don't edit by hand. |

## Years

Years are **astronomical**: 1 BC = `0`, 2 BC = `-1`, 200 BC = `-199`, AD 1 = `1`. (The historical calendar has no year 0.) The timeline runs from `-29999` (30,000 BC) to `2026`.

## Adding an event

```yaml
- id: siege-of-fort-zeelandia            # unique, lowercase-kebab-case
  title: { zh-TW: 熱蘭遮城之役, en: Siege of Fort Zeelandia }
  altNames:                              # optional
    - { zh-TW: …, en: … }
  summary:
    zh-TW: …
    en: …
  start: { year: 1661, month: 4, day: 30 } # or just: start: 1661
  end: { year: 1662, month: 2, day: 1 }    # optional; omit for a single date
  precision: day                         # day | month | year | decade | century | millennium
  approximate: false                     # true shows "約 / c."
  categories: [war]                      # see src/lib/categories.ts
  regions: [taiwan]                      # free tags; `taiwan` gets an importance boost
  importance: 4                          # editor estimate 1–5 (used until Wikipedia scores exist)
  importanceBoost: 0                     # optional, -2..2, nudges the computed score
  importanceLocked: false                # optional, true = always use `importance`
  locations:
    - { place: tainan-anping, role: primary }
    - { place: xiamen, role: origin }        # origin → destination draws an arc
    - { place: tainan-anping, role: destination }
  relations:                             # the inverse is added automatically
    - { event: dutch-formosa, type: part_of }
    - { event: kingdom-of-tungning, type: causes }
  perspectives:                          # for contested events, see docs/EDITORIAL.md
    - view: taiwan
      text: { zh-TW: …, en: … }
  wikipedia: { en: Siege of Fort Zeelandia, zh: 熱蘭遮城之役 }  # article titles; used for links and importance
  sources:
    - { resource: andrade-lost-colony }          # an entry in resources.yaml
    - { url: "https://…", title: { zh-TW: …, en: … } }
```

**Location roles:** `primary` (where it happened), `secondary` (also involved), `origin` and `destination` (movements; every origin is linked to every destination with an animated arc), `area`.

**Relation types:** `causes`, `caused_by`, `part_of`, `has_part`, `precedes`, `follows`, `related`.

## Adding a place

```yaml
- id: tainan-anping
  coords: [120.1606, 23.0016]   # [longitude, latitude]
  names:
    - { zh-TW: 大員, en: Tayouan, to: 1661 }
    - { zh-TW: 安平, en: Anping, from: 1662 }
  modern: { zh-TW: 臺南市安平區, en: "Anping, Tainan" }
```

YAML tip: inside `{ … }`, put text that contains a comma in quotes (`en: "Anping, Tainan"`).

## Adding a resource link

Add an entry to `data/resources.yaml`. It appears in the app's 參考資源 / Resources dialog straight away:

```yaml
- id: my-source
  name: { zh-TW: 中文名稱, en: English name }
  url: https://example.org/      # optional for books
  type: archive                  # see resourceTypes in config.yaml
  lang: [zh, en]
  description: { zh-TW: …, en: … }  # optional
```

## Importance（重要度）

"Major" events are decided from Wikipedia:

1. `npm run importance` reads each event's `wikipedia` titles and fetches
   - the number of Wikipedia language editions with an article (from Wikidata), and
   - page views on English and Chinese Wikipedia over the last 12 months.
2. These are log-scaled into a 0–1 score (`src/lib/importance.ts`): 50 % language editions, 25 % English views, 25 % Chinese views, then mapped to 1–5.
3. Events tagged with a region in `regionBoost` (`taiwan: +1`) get a boost, so Taiwan's history is not drowned out by globally famous events. `importanceBoost` lets editors nudge one event.

The result is saved to `data/importance.json`. A GitHub Action (`.github/workflows/importance.yml`) refreshes it on the 1st of every month and can also be run by hand from the Actions tab. Until it has run, events use the editor estimate in `importance`, and the app marks them as provisional.

The wider the selected time range, the higher the minimum importance shown: > 1,000 years → 4+, > 200 → 3+, > 50 → 2+, otherwise all. "Show all" turns this off.

## Imported events（自動匯入）

Of the sources in `data/resources.yaml`, only Wikipedia/Wikidata publishes events as structured data; the museums and archives don't offer machine-readable event lists. `npm run import` (`scripts/import-wikidata.ts`) pulls events in Asia from Wikidata:

- **What:** battles, wars, sieges, invasions, treaties, rebellions, revolutions, coups, massacres, protests, earthquakes, epidemics, major elections and other historical events.
- **Where:** a location with coordinates in South, Southeast, East or Central Asia.
- **How notable:** enough Wikipedia language editions to count as notable (5–15 depending on the type). Events in Taiwan, Penghu, Kinmen and Matsu need only 2.
- **Skipped:** anything already curated in `data/events/` (matched by Wikipedia title).

Each imported event gets the Wikidata label as its title, the Wikidata short description as its summary, its places, its "part of" links, Wikipedia and Wikidata links, and an importance from the number of language editions (+1 in Taiwan). It is marked `reviewed: false` and shown in the app with a **待審 / Unreviewed** badge. The 含自動匯入 / Include imported checkbox hides them.

**To run it:** Actions → **Import events from Wikidata** → *Run workflow*. It also runs monthly. It writes `data/imported/` on the `data/wikidata-import` branch and opens a pull request to look over before merging. (If GitHub refuses to let the workflow open the pull request, allow it under Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests", or open it by hand.)

**To review or rewrite an imported event:** move it into a file in `data/events/`, write a proper summary following [EDITORIAL.md](EDITORIAL.md), and remove `reviewed: false`. Later imports skip it because it's now curated.
